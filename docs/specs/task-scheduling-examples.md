# Як запланувати задачу: конкретні приклади

Правила: [ADR-009](../decisions/0009-task-planning-windows.md).
Кроки «Створити» стосуються Create; кроки «Редагувати» — повного Edit
(посилання Edit на сторінці задачі). Дати й час — у часовому поясі Vikunja.
Після створення натиснути Create one-time task / Create timed session / Create recurring task;
після редагування — Save changes. Незбережені поля не змінюють задачу.

New task із конкретного дня календаря може вже мати заповнений план.
Для прикладу лише з дедлайном очистити Planned finish; у повному Edit —
Available from date та Planned finish date. Інакше наявний план також збережеться.

## «Магазин потрібно відвідати до сьогоднішніх 12:00»

**Створити:** Do once. Schedule a timed session вимкнено. Deadline — сьогодні,
Deadline time — 12:00. Planned finish і Start можна не задавати.

**Редагувати:** Deadline date — сьогодні, Deadline time — 12:00.
Available from та Planned finish залишити порожніми для задачі лише з дедлайном.

**Поведінка:** задача є в Today. Після 12:00 незавершена задача
прострочена (Overdue). Тривалість не потрібна. Reminder додається окремо,
якщо потрібне сповіщення; він не створюється автоматично.

**Vikunja:** `due_date` — сьогодні о 12:00; `start_date` і `end_date`
не задані. Для точного часу немає мітки `vbu:date-only`.

Це погоджене значення прикладу користувача «о 12:00 йду в магазин»:
користувач уточнив, що до 12:00 вже треба виконати, а після — показувати
прострочення. Не трактувати це як запланований початок.

## «Починаю поїздку о 12:00, планую витратити годину»

**Створити:** Do once → Schedule a timed session. Start date — сьогодні,
Start time — 12:00; Duration — 1 година. Окремо вибрати Extra time to finish.
Наприклад, 30 хвилин означають дедлайн завершення о 13:30.

**Редагувати:** Start date/time — сьогодні о 12:00. Відкрити
Set duration and extra time, вибрати Duration — 1 година,
Extra time to finish — 30 хвилин і натиснути Apply duration, потім Save changes.
Альтернатива: безпосередньо задати End date/time — 13:00 і Due date/time — 13:30
того самого дня. Зміна лише Start у повному Edit не пересуває End і Due автоматично.

**Поведінка:** запланований сеанс 12:00–13:00. У цьому прикладі
прострочення настає після 13:30, а не після початку о 12:00.
Наявна форма Job вимагає додатну тривалість і додатне вікно завершення.

**Vikunja:** `start_date` — 12:00, `end_date` — 13:00,
`due_date` — 13:30; службова мітка `vbu:job`.
Деталі: [Job](recurring-jobs.md).

## «Сходити в магазин будь-коли сьогодні між 12:00 і 18:00»

**Створити:** Do once, Schedule a timed session вимкнено. Planned finish — сьогодні,
Planned finish time — 18:00. Автоматичний початок означає момент створення;
щоб задати саме 12:00,
відкрити Change availability → Add time → Start time (optional) — 12:00, потім Done.
Якщо дата початку інша, спочатку вибрати сьогодні через Change availability,
потім знову відкрити календар, щоб додати час.
Deadline можна не задавати.

**Редагувати:** Available from date/time — сьогодні о 12:00, Planned finish date/time — сьогодні
о 18:00. Deadline date/time залишити порожніми, якщо обов'язкового строку немає.

**Поведінка:** доступне вікно 12:00–18:00. Задача є в Today,
бо завершити її заплановано сьогодні. У цьому вікні вона також є в Active work.
Пропущений план позначається Missed plan, а не Overdue.
Якщо 18:00 — обов'язковий граничний строк, додатково задати Deadline 18:00.

**Vikunja:** `start_date` — 12:00, `end_date` — 18:00;
`due_date` відсутній, якщо окремий дедлайн не задано.

**Обмеження:** якщо сама поїздка займає годину, ця година не є шириною
вікна. Окремого поля оцінки зусиль для такого плану зараз немає.
Job не є заміною: він задає конкретний сеанс, наприклад 14:00–15:00.

## «Один раз сходити на пікнік протягом місяця»

**Створити:** Do once, Schedule a timed session вимкнено. Planned finish — останній бажаний день
місяця. Start за замовчуванням — момент створення; його можна змінити.
Revisit — звичайна необов'язкова мітка для справ, до яких хочеться повертатися.

**Редагувати:** Available from date — бажаний початок, Planned finish date — останній день вікна.
Щоб завершення було наприкінці дня, прибрати Planned finish time. Якщо міняєш тільки дату, наявний час
зберігається. Available from у повному Edit не підставляється автоматично.

**Поведінка:** одна задача, а не щомісячний повтор. Active work показує її
протягом доступного вікна. Today включає її за плановим завершенням або
дедлайном, а не просто тому, що настав Start. Завершити потрібно один раз.

**Vikunja:** `start_date` і `end_date` — межі вікна; recurrence відсутня.
Дата завершення без часу означає кінець дня. Тривалість самого пікніка
окремим полем поки не зберігається.

## «Робити це щомісяця»

**Створити:** Repeat → Unit: Months. Every стає 1, Repeat timing — Fixed schedule.
Задати First due date і, за потреби, Due time.
Це регулярна справа, на відміну від «один раз протягом місяця».

**Редагувати:** Repeat → Unit: Months; дату поточного повтору змінити через
Due date/time. Start date/time визначає доступність. Це змінює живу серію,
а не окремий майбутній повтор; історія завершень не переписується.

**Поведінка:** після завершення Vikunja поновлює ту саму задачу.
More → Recurring показує її частоту. Доступність задається окремо.

**Vikunja:** `due_date` — дата поточного повтору, native `repeat_mode` /
`repeat_after` — правило повторення. [Деталі](task-planning-ui-proposal.md).

## Неоднозначне «о 12:00»

Available now у Create означає час збереження на сервері, до секунди.
Явно вибрана дата без часу означає початок цього дня. Без плану Start
залишається порожнім. Для вже минулого завершення автоматичний Start
залишається на історичній даті, щоб не опинитися після кінця вікна.

Спочатку визначити, що означає пропустити 12:00:

- До цього часу вже треба виконати → Deadline.
- У цей час починаю сеанс відомої тривалості → Schedule a timed session.
- Лише з цього часу можна починати → Available from / Start.

Точний початок без тривалості, який не є дедлайном, залишається окремим
непідтриманим сценарієм. Не підміняти його дедлайном або вигаданою тривалістю.
